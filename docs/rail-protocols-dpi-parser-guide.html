Cyber Vision · DPI Parser Guide

Rail Signaling Protocols

EMP (I-ETMS / PTC over AAR Class D) and ATCS (relay-feed codeline) — everything a developer needs to build a Cyber Vision dissector, plus the labeled-corpus format to train and validate it against.

Fidelity, up front. ATCS's wire structure was validated live against a real ATCS Monitor 4.1.0 decoder — it accepts and correctly decodes PacketArch's generated frames. EMP / Class D is built from the public 2010 S-9356 draft + AAR MSRP K-II (2005): structurally authoritative, not yet checked against a current-revision capture. Application-layer message content is synthetic for both — the AAR ITC catalog and per-territory codeline databases are proprietary. Every field carries a confidence tier; weight your training accordingly.

The labeled corpus — your training data

A generation run with export_labeled_corpus=true emits three files alongside the PCAP.

FileContents
<stem>.pcapThe combined capture (Ethernet/IP/TCP or UDP).
<stem>.labels.jsonlOne JSON object per packet, index-aligned 1:1 with the PCAP — per-field ground truth.
<stem>.labels.meta.jsonRun summary: schema version, counts, protocol breakdown, field vocabulary.

1.1Per-packet label record

KeyPresentMeaning
pktalways0-based index into the PCAP (packets[pkt] is this frame).
ts_msalwaysTimestamp (ms).
flow_idalwaysOriginating flow.
protocolalwaysemp, atcs, unknown, …
typealwaysEvent type, e.g. atcs_codeline_indication, tcp_syn (may be null).
l7_offsetif knownByte offset where the L7 unit begins (§1.3).
encodingalwaysbinary (both protocols today) or ascii_hex (§1.2).
fieldsif labeledArray of field entries. Absent for unlabeled packets (handshake, keep-alives).

Each entry in fields carries off, len, field (dotted name), value, synthetic, confidence, and — for ATCS addresses only — subfields and an optional note.

1.2Mapping a field to bytes — encoding

  • binary (both EMP and ATCS today): the field is packet[l7_offset + off : l7_offset + off + len].
  • ascii_hex (defined alternate, not currently emitted): the L7 payload is ASCII-hex text; a field is the 2·len hex chars at l7_offset + 2·off. off/len index the decoded frame.

1.3l7_offset — do not hardcode 54

l7_offset is derived per packet as len(packet) − len(L7). Because PacketArch fingerprints the TCP stack, frames carry TCP options, so the L7 start is frequently 66, not the classic 14 + 20 + 20 = 54. Always read the field; never assume a fixed header length. Nested: offsets are relative to the outermost L7 unit — EMP rides inside Class D, so emp.* offsets are Class-D-relative and EMP begins at Class-D offset 12.

1.4Confidence tiers — the signal aspects

The tiers map to railroad signal aspects: spec is clear, spec_legacy is approach, synthetic is stop. Train the matcher on structure (spec / spec_legacy); treat synthetic bytes as "a payload of length N here," never as ground truth.

TierMeaningHow to use it
specCurrent-source verified, or corpus-validated against the live decoder.Ground truth for structure.
spec_legacySpec-derived from a legacy/draft revision (2010 S-9356; K-II 2005).Trust structure; don't assume exact current values.
provisionalReconstructed; reproduces known values, positions unconfirmed.Use cautiously.
syntheticPlausible but invented — no public source.Don't key the classifier on these values.

.meta.json gives schema_version (=1), packet_count, labeled_count, protocol_counts, and field_vocabulary (sorted distinct field names) — an index of what your dissector must cover.

EMP over AAR Class D

EMP is the AAR Interoperable Train Control (I-ETMS / PTC) application envelope exchanged between back-office servers, wayside interface units, and locomotive computers. EMP never rides bare on TCP — AAR S-9356 Class D is the transport: the TCP payload is Class D header (12B) + body + ETX, and for a data message the body is the EMP envelope.

2.1Transport identification

  • TCP. Default port 3001 — but this is a documented Siemens wayside vendor default and is configurable; there is no universal Class D port. Do not classify on port alone.
  • Classify on framing invariants: [0]==0x02 (STX) & [1]==0x02 (version), last byte 0x03 (ETX), data_length at [8:12] consistent with the payload, and for a Data message [12]==0x04 (EMP version).
  • Cross-reference: Fortinet's ITCM.Class.D signature is a useful independent oracle.

2.4Parsing algorithm

parse_tcp_payload(buf):
  if buf[0]!=0x02 or buf[1]!=0x02 or buf[-1]!=0x03: # not Class D
  commid = u32be(buf[2:6]); mtype = buf[6]; dlen = u32be(buf[8:12])
  if dlen != len(buf) - 13: # framing error (or needs reassembly)
  body = buf[12:12+dlen]
  if mtype == 1:                     # Data → EMP
    emp = body
    assert emp[0] == 4              # EMP version
    msg_type  = u16be(emp[1:3]); body_size = u24be(emp[5:8]); vhdr = emp[8]
    sender, i = read_cstring(emp, 13)
    dest,   j = read_cstring(emp, i)
    payload   = emp[13+vhdr : len(emp)-4]
    crc32     = s32be(emp[-4:])       # verify over emp[:-4] — strong signal
  elif mtype == 2: acked = u32be(body[0:4])
  elif mtype == 3: nak = u32be(body[0:4]); err = body[4]
  elif mtype == 4: # keep-alive

2.5Trust vs. ignore

  • Trust legacy: all Class D + EMP-envelope structure — framing, STX/ETX, COMMID, data_length, EMP version, sizes, TTL, QoS, the NUL-terminated addresses, the CRC-32.
  • Don't overfit synthetic: emp.msg_type values and payload schemas. The real AAR ITC catalog is proprietary. Classify EMP on the envelope, not on specific application message numbers.

ATCS relay-feed codeline

ATCS (AAR MSRP Section K-II, formerly Spec 200) is a legacy 900 MHz RF codeline. The only IP-observable form is the ATCS Monitor relay feed: base-station relays decode the RF and stream decoded frames over IP to dispatch. Cyber Vision sees this feed, never the RF. This layout was validated live against a real ATCS Monitor 4.1.0 decoder.

3.1Feed transport identification

  1. Subscriber opens TCP to port 4802 (relay control; configurable).
  2. Subscriber sends ASCII ATCSMON <version>\n (subscribe).
  3. Relay replies PORT <n>\n, assigning a UDP data port (30000+).
  4. Relay streams binary ATCS frames over UDP, one frame per datagram.
  5. The subscriber's version string doubles as the keep-alive.
Classify the UDP codeline frames on frame self-consistency (§3.3–3.4) — both CRC-16/X.25 checks passing is a near-zero false-positive signal. Ports are configurable; don't rely on them alone.

3.3The two CRCs — CRC-16/X.25 (your strongest classifier)

Both framing CRCs are CRC-16/X.25 (HDLC FCS): poly=0x1021, init=0xFFFF, RefIn=RefOut=true, XorOut=0xFFFF, stored little-endian. Header CRC covers [0:3]; datagram CRC covers [5 : len−2]. Both passing over their exact spans is a near-zero false-positive ATCS signal — use it as your primary matcher.

def crc16_x25(data):
  crc = 0xFFFF
  for b in data:
    crc ^= b
    for _ in range(8):
      crc = (crc >> 1) ^ 0x8408 if (crc & 1) else (crc >> 1)
  return crc ^ 0xFFFF          # stored LE: bytes([crc & 0xFF, crc >> 8])
# header  : crc16_x25(frame[0:3])  == frame[3] | frame[4]<<8
# datagram: crc16_x25(frame[5:-2]) == frame[-2] | frame[-1]<<8

3.4Frame-length field (block_count / pad_bits)

The RF header encodes length as Reed-Solomon blocks of 60 frame-bits each. The real decoder rebuilds the expected length and rejects a mismatch. For a total frame of L bytes:

block_count = ceil(8 * L / 60)          # = ceil(2 * L / 15)
pad_bits    = 60 * block_count - 8 * L   # always 0..59

Recompute from the received datagram length and confirm against [2]/[1] as an integrity check.

3.5Address encoding — the gotchas

  • Modified BCD, high nibble first. Two decimal digits per octet.
  • A zero digit is nibble 0xA, not 0x0. e.g. 28 A2 A6 3A A7 → 2 8 0 2 0 6 3 0 0 7 = 2802063007.
  • Destination first, then source.
  • Two forms: 7-series (14 digits) T-RRR-CCC-AAA-XXXX (Type/Railroad/Codeline/Address/eXtension); 5-series (10 digits) T-RRR-XX-AAAA.
  • Type digit = role: 1 locomotive, 2 office/dispatch, 3 base station, 5/7 wayside (MCP). Wayside 7-series extension 0202 = indications, 0101 = command & control.
def decode_atcs_addr(byts):        # nibble 0xA == digit 0
  return "".join(("0" if n == 0xA else str(n))
                 for x in byts for n in (x >> 4, x & 0xF))
Decoded ATCS addresses are directly usable for Cyber Vision asset identity: railroad + codeline + serial + role. This is the most valuable DPI output for the protocol.

3.6GFI / Group and sequences

[5] = (GFI << 4) | Group. Observed: 0x68=GFI6/Grp8, 0x25=GFI2/Grp5, 0x6C=GFI6/Grp12, 0x2D=GFI2/Grp13. send/receive_sequence = the byte >> 1 (LAPB-style N(S)/N(R); low bit 0).

3.7Deriving UsrData length

The decoder derives it from the received datagram size (one frame per UDP datagram) minus the fixed overhead — do the same:

usrdata_len = total_frame_len
            - 5   # RF header
            - 5   # network header [5:10]
            - dst_bytes - src_bytes   # from the [9] nibbles
            - 1   # facility length
            - 5   # transport header
            - 2   # datagram CRC
            - (4 if vital else 0)     # inner vital CRC

3.8Vital CRC (vital messages only)

When the vital flag in message_length_vital is set, a 31-bit K-II vital CRC (4 octets) precedes the datagram CRC inside the L7 region. Polynomial low-mask 0x520D8A81, data processed LSB-first, register emitted least-significant-octet first; coverage = address-length octet [9] through end of L7 data. Verified against the K-II mandatory vector 01 02 → 25 ED BD 70. The outer datagram CRC still wraps it.

3.9Parsing algorithm

parse_atcs_datagram(f):                 # f = one UDP payload
  if crc16_x25(f[0:3])  != le16(f[3:5]): # reject: bad header CRC
  if crc16_x25(f[5:-2]) != le16(f[-2:]): # reject: bad datagram CRC
  gfi, group = f[5] >> 4, f[5] & 0x0F
  sseq, rseq = f[7] >> 1, f[8] >> 1
  src_d, dst_d = f[9] >> 4, f[9] & 0x0F
  o = 10
  dst = decode_atcs_addr(f[o : o+ceil(dst_d/2)]); o += ceil(dst_d/2)
  src = decode_atcs_addr(f[o : o+ceil(src_d/2)]); o += ceil(src_d/2)
  facility_len = f[o]; o += 1 + facility_len
  msg_num = f[o]>>1; part = f[o+1]>>1; vital = f[o+2] & 1
  label = be16(f[o+3:o+5]); o += 5
  usr_end = len(f) - 2 - (4 if vital else 0)
  usrdata = f[o : usr_end]

3.10Trust vs. ignore

  • Trust spec (corpus-validated live): the 5-byte RF header, both CRC-16/X.25 fields, gfi_group, spare, sequences, the address-length octet, the dest-first BCD addresses, the facility length.
  • Trust structure legacy: the transport header layout and the vital CRC (K-II 2005; may drift).
  • Don't overfit synthetic: UsrData content — per-territory codeline semantics live in proprietary .mcp databases. Treat UsrData as an opaque length-N blob; extract identity from the addresses.
§4

Classifier design recommendations

  1. Identify on framing invariants, not ports. 3001 (EMP) and 4802/30000+ (ATCS) are configurable vendor defaults.
    • EMP: [0]==0x02 && [1]==0x02 && [-1]==0x03 and data_length matches; then EMP [12]==0x04.
    • ATCS: both CRC-16/X.25 checks pass over their exact spans — high confidence on its own.
  2. Use CRCs as positive signals, not just error detection — a self-verifying frame is almost certainly the protocol.
  3. Extract asset identity — the DPI payoff: EMP src/dst_addr (aar.<class>.<name>) → device + role; ATCS BCD addresses → railroad, codeline, serial, and role (type digit + extension). Each distinct wayside MCP is a component.
  4. Don't learn synthetic content as ground truth — emp.msg_type values, EMP payload schemas, ATCS UsrData bytes.
  5. Handle TCP reassembly for EMP (Class D can span segments; use data_length). ATCS is one frame per UDP datagram — no reassembly.
§5

Open items & fidelity caveats

  • synthetic (won't change without proprietary sources): EMP application message catalog (real message-type IDs + payload schemas), ATCS territory-specific UsrData semantics.
  • legacy current-revision drift: Class D is the 2010 S-9356 draft; ATCS transport header + vital CRC are K-II 2005 v4.0. A current-revision capture (a BOS↔WIU trace; an ATCS Monitor .log) would promote them to spec.
  • Resolved / validated: the ATCS relay-feed framing, both CRC-16/X.25 fields, the frame-length field, GFI|Group, sequences, and address encoding — all confirmed against the live ATCS Monitor 4.1.0 decoder.

Generating & reading the corpus

Set export_labeled_corpus=true on the generation request for the ptc_freight_corridor (EMP) or atcs_signaling_territory (ATCS) scenario. You get .pcap + .labels.jsonl + .labels.meta.json.

import json
from scapy.utils import rdpcap
pkts = rdpcap("run.pcap")
for rec in map(json.loads, open("run.labels.jsonl")):
  if not rec.get("fields"): continue
  raw, l7 = bytes(pkts[rec["pkt"]]), rec["l7_offset"]
  for f in rec["fields"]:                  # encoding == "binary"
    field_bytes = raw[l7 + f["off"] : l7 + f["off"] + f["len"]]
    # f["field"], f["value"], f["confidence"], f["synthetic"]
